# 🍨 BR Simulator — 포장 용기 에셋 가이드

화면②(메뉴 제작 화면)에서 아이스크림을 용기에 담는 연출에 쓰이는 아트 리소스입니다.
모든 이미지는 **투명 배경 PNG**(2x 해상도), 코지 파스텔 스타일입니다.

> ⚠️ **네이밍 안내**: 용기 이름은 상표 이슈가 있는 기존 사이즈명 대신,
> 기획서대로 **잇코~록코**(일본어 「N個」 = "N개" 조수사)로 통일했습니다. 파일·폴더명은 로마자(ikko…)로 표기합니다.

---

## 1. 용기 6종 & 담기 방식

용기 크기는 **담을 수 있는 맛 개수**로 구분합니다. 이름은 담기는 개수 그 자체를 뜻합니다(1個=잇코 … 6個=록코).

| 코드(폴더/파일) | 이름 | 뜻 | 맛 개수 | 담기 방식 | 캔버스(px) |
|------|:----:|:----:|:------:|-----------|-----------|
| `01_ikko` | 잇코 | 1個 | 1 | 🍦 스쿱(동그란 볼) | 608 × 602 |
| `02_niko` | 니코 | 2個 | 2 | 🍦 스쿱(동그란 볼) | 688 × 682 |
| `03_sanko` | 산코 | 3個 | 3 | 🍕 웨지(피자 조각) | 768 × 762 |
| `04_yonko` | 욘코 | 4個 | 4 | 🍕 웨지 | 848 × 840 |
| `05_goko` | 고코 | 5個 | 5 | 🍕 웨지 | 928 × 920 |
| `06_rokko` | 록코 | 6個 | 6 | 🍕 웨지 | 1008 × 998 |

- **잇코·니코**: 스쿱으로 퍼서 담기 때문에 **동그란 볼**이 올라감 (1개 / 2개).
- **산코~록코**: 스페이드로 담기 때문에 **피자 조각(웨지)** 로 맛별 슬롯을 채움. 슬롯 수 = 맛 개수.

## 2. 폴더 구조

```
icecream_cups/
├── README.md                  ← 이 문서
├── 01_containers_empty/       ← 빈 용기 (화면② 베이스, 위에서 내려다본 뷰)
│     cup_01_ikko_top.png … cup_06_rokko_top.png  (+ .svg)
├── 02_flavor_overlays/        ← 맛별 오버레이 (핵심! 베이스 위에 올림)
│     01_ikko/  … 06_rokko/     (용기별 슬롯 × 20맛 = 총 420개)
├── 03_fill_states/            ← 단계별 미리 합성본 (오버레이 대신 통짜로 쓸 때)
│     cup_XX_fill1.png … fillN.png
├── 04_filled_examples/        ← 완성 예시 (전 슬롯 채운 모습)
│     cup_XX_filled.png
├── 05_packaging_closed/       ← 뚜껑 닫힌 포장 상태 (화면③ 포장/선택용, 사이드뷰)
│     cup_XX_lid.png
├── _preview/                  ← 팀 확인용 시트·팔레트·데모 (게임에 안 씀)
│     _flavor_palette.png, _demo_flavors.png, _sheet_top.png, _sheet_filled.png, _prog_*.png
├── _source/                   ← 재생성용 데이터·스크립트 (flavors.csv, *.py)
└── _archive/                  ← 초기 버전·폐기 파일 (무시해도 됨)
```

`XX` = 용기 코드 (`01_ikko` … `06_rokko`).

## 3. 화면②에서 쓰는 법 (권장: 오버레이 스택)

한 맛 담을 때마다 오버레이를 **한 장씩 위로 얹는** 방식입니다.

1. **베이스**로 `01_containers_empty/cup_{용기}_top.png` 를 깐다.
2. 맛을 담을 때마다 `02_flavor_overlays/{용기}/` 에서 해당 파일을 순서대로 올린다.
   - 웨지 용기: `slot1_...` → `slot2_...` → … (슬롯 번호 = 담긴 순서)
   - 스쿱 용기: `pos1_...` → `pos2_...`
3. **베이스와 오버레이는 캔버스 크기·좌표가 100% 동일** → 리사이즈·오프셋 없이 (0,0)에 그대로 겹치면 정렬됨.

> 예) 고코(5맛)에 딸기 → 치즈케이크 → 민트초코칩 순으로 담기면
> `cup_05_goko_top.png` + `slot1_FLV-007_*` + `slot2_FLV-005_*` + `slot3_FLV-001_*`

`_preview/_demo_flavors.png` 가 정확히 이 방식으로 합성한 결과입니다.

### 대안: 미리 합성된 단계별 이미지
오버레이 합성이 부담되면 `03_fill_states/cup_{용기}_fill{K}.png` 를 K(담긴 개수)에 따라 통째로 교체해도 됩니다. (단, 맛 조합은 고정된 기본 순서)

## 4. 맛 20종 매핑

파일명 규칙: `slot{슬롯}_{flavor_id}_{맛이름}.png` (스쿱은 `pos{자리}_...`)

- `flavor_id` 는 `_source/flavors.csv` 의 ID와 1:1 대응 (FLV-001 ~ FLV-020).
- 색상은 CSV의 `color_hex` 를 파스텔 톤으로 살짝 순화한 값. 원본 hex·언락 레벨은 `_preview/_flavor_palette.png` 참조.
- 초코칩·쿠키·퍼지·프랄린 등 8종은 알갱이(스펙클)가 들어가 있음.

전체 색상 한눈에 보기 → **`_preview/_flavor_palette.png`**

---

## 5. 규격 & 참고

- 포맷: PNG, 투명 배경, 2x 해상도. (원본 벡터가 필요하면 각 폴더의 `.svg`)
- 좌표계: 같은 용기의 빈 베이스 / 오버레이 / fill_states / filled 는 **모두 동일 캔버스**라 그대로 포갬.
- 색·모양을 바꾸려면 `_source/` 의 `flavors.csv` 수정 후 `gen_flavors.py` 재실행 → 420개 전체 재생성. (스크립트 사이즈 키도 `01_ikko`~`06_rokko`로 반영됨)
- 상표 주의: 용기 사이즈명은 잇코~록코로 통일(상표 이슈 있는 기존 사이즈명 미사용). 로고도 실제 상표 워드마크 대신 자체 아이스크림 콘 엠블럼 사용. 게임 자체 로고가 생기면 교체 가능.
